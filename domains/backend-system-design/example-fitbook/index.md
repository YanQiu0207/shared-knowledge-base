# 实战示例：FitBook 课程预约系统

## 结论

本目录用一个虚构但贴近真实的项目，完整走一遍[中小型后端项目系统设计方法论](../methodology.md)的五个阶段，产出全部设计工件，供后续项目参考。

项目背景：一家有 3 名教练的健身工作室，目前用微信群接龙排课，经常超订和漏记，需要一个课程预约后端。开发者 1 人。

## 使用说明

- 示例中的业务数字（用户量、QPS）为合理假设，真实项目替换为自己的估算即可
- 真实项目建议将这些文档放在项目仓库的 `docs/design/` 下，ADR 每条一个文件放 `docs/adr/`
- 本示例刻意保留了两处「差点过度设计」的决策过程（ADR-001 与 ADR-003），演示反过度设计清单如何实际起作用
